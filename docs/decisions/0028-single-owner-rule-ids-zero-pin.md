# 0028. Govern docs as contracts: single-owner rule IDs, zero phrase-pins, a conformance harness, and an LLM judge for free prose

## Status

Accepted

## Context

Normative rules were duplicated as prose across skill and contract docs and enforced by brittle exact-phrase `assert.match` pins in `test/contracts/*.test.mjs`: duplicates drifted into contradiction, every legitimate rewording broke tests, and at least one pin enforced factually wrong framing ([issue 1147](https://github.com/mfittko/dev-loops/issues/1147), [issue 1260](https://github.com/mfittko/dev-loops/issues/1260)). The rule-ID ownership foundation landed via [PR 1183](https://github.com/mfittko/dev-loops/pull/1183), establishing `skills/docs/contract-style-guide.md` as the canonical owner of the style rules (`STYLE-SINGLE-OWNER`, `STYLE-REFERENCE-BY-ID`, `STYLE-ID-STABILITY`, and peers) and `skills/docs/required-rules.json` as the completeness manifest, now covering 166 required rule IDs. The L2/L3 state-machine conformance and invariant harness followed for [issue 1148](https://github.com/mfittko/dev-loops/issues/1148) via [PR 1189](https://github.com/mfittko/dev-loops/pull/1189). Phrase-pin tests were then migrated cluster by cluster — gate contracts ([PR 1191](https://github.com/mfittko/dev-loops/pull/1191)), the public dev-loop contract ([PR 1194](https://github.com/mfittko/dev-loops/pull/1194)), queue/board and conductor routing ([PR 1197](https://github.com/mfittko/dev-loops/pull/1197)), a final small-docs sweep ([PR 1204](https://github.com/mfittko/dev-loops/pull/1204)) — to the declared zero-pin end state of [issue 1205](https://github.com/mfittko/dev-loops/issues/1205), completed via [PR 1206](https://github.com/mfittko/dev-loops/pull/1206). Finally, [PR 1262](https://github.com/mfittko/dev-loops/pull/1262) replaced the README's prose-pin assertions with the semantic rubric in `docs/readme-audit-rubric.md`.

## Decision

Every normative rule gets exactly one owning contract doc and a stable uppercase rule ID declared with an HTML `<!-- rule: ... -->` marker and registered in `skills/docs/required-rules.json`; all other docs reference the ID instead of restating the prose, and `scripts/docs/validate-rule-ownership.mjs` enforces single ownership and manifest completeness. Semantic changes retire the old ID and mint a new one through a dedicated semantic-change issue — silent mutation of a rule under a stable ID is forbidden. We drove the phrase-pin test suite to a declared zero-pin end state rather than tolerating a residual set, rejecting continued exact-prose pinning as an enforcement mechanism outright. Where docs claim behavior, the L2/L3 harness (`scripts/docs/validate-state-machine-conformance.mjs`) binds those claims to the exported state machines: L2 checks doc-to-code conformance, L3 checks graph invariants, and the ownership validator's contradiction scan stays deliberately lexical, leaving behavioral contradictions to the harness and semantic ones to the gate lens. Free prose like the README is audited on demand by an LLM judge against the property rubric in `docs/readme-audit-rubric.md` — the judge tolerates rewording and fails only on genuine absence or contradiction — while deterministic guarantees (link resolution via `scripts/docs/validate-links.mjs`, version drift) stay mechanical; we rejected wiring the LLM audit into CI, keeping the agent harness as its runtime.

## Consequences

How any behavioral rule is authored, owned, and validated is now fixed: own it in one doc, tag it with a marker and registered ID, and wire the harness if it claims machine behavior. This reversed the doc-enforcement modality from prose-pinning to ID ownership — rewordings no longer break tests, and duplicated rules can no longer drift into contradiction because duplication itself fails validation. Conflicts have a deterministic resolution: the document owning the referenced rule ID wins until a semantic-change issue replaces the rule. The split between judgment and mechanism is explicit — framing, accuracy, and completeness of free prose may be semantically judged, while links, manifests, ownership, and state-machine conformance must stay mechanical checks. The costs are ceremony (every new normative rule needs an ID, a marker, and a registry entry) and a semantic audit that runs only when an operator invokes it, so README drift is caught on demand rather than on every commit.
