# 0019. Make the runtime harness-agnostic: HarnessAdapter seams, generated per-harness assets, dev-loops identity

## Status

Accepted

## Context

The runtime was hard-coupled to the Pi agent harness: the extension bound directly to Pi's `ExtensionAPI`/`ExtensionContext` types, operational env vars carried the `PI_*` prefix, skills and agents existed only as Pi assets, and the package shipped under a harness-prefixed package identity — blocking use under Claude Code or any other harness ([issue 765](https://github.com/mfittko/dev-loops/issues/765), [issue 770](https://github.com/mfittko/dev-loops/issues/770)). Decoupling landed as a sequence: the context/exec adapter seam ([PR 783](https://github.com/mfittko/dev-loops/pull/783)), the package rename ([PR 780](https://github.com/mfittko/dev-loops/pull/780)) and repo rename ([PR 791](https://github.com/mfittko/dev-loops/pull/791)), the extension-surface adapter ([PR 812](https://github.com/mfittko/dev-loops/pull/812)), the neutral run-id contract ([issue 771](https://github.com/mfittko/dev-loops/issues/771), [PR 813](https://github.com/mfittko/dev-loops/pull/813)), generated Claude agents and skills ([issue 772](https://github.com/mfittko/dev-loops/issues/772), [PR 814](https://github.com/mfittko/dev-loops/pull/814)), Claude hooks ([PR 815](https://github.com/mfittko/dev-loops/pull/815)) and the plugin manifest ([PR 821](https://github.com/mfittko/dev-loops/pull/821)), and the deliberately breaking env-var rename ([issue 905](https://github.com/mfittko/dev-loops/issues/905), [PR 907](https://github.com/mfittko/dev-loops/pull/907)). The seams live in `packages/core/src/harness/`; the Pi extension side integrates through `extension/pi-extension-adapter.ts`.

## Decision

We route all harness coupling through two frozen, validated adapter seams in core: a context seam (`createHarnessAdapter` — cwd, env, interactivity, repo root, answering "where am I running") and an extension-surface seam (process exec, session lifecycle events, slash-command registration, UI, answering "how do I talk to the harness"), each with Pi, Claude, and noop/test implementations. The Pi import boundary is owned by a single extension module that re-exports the Pi types, and a contract test fails any `@earendil-works/pi-*` import in CLI/lib sources and any `PI_*` env read outside the allowlisted adapter-boundary files. A neutral `DEVLOOPS_RUN_ID` async-context contract replaces Pi-specific run-id plumbing: dev-loops mints and propagates only the neutral var, honoring the Pi-runtime-injected `PI_SUBAGENT_RUN_ID` as an externally-injected alias inside the run-context modules alone. The `.claude` tree — agents, skills, hooks, plugin manifest — is generated from the canonical Pi source tree by a generator whose `--check` mode fails CI on drift; we rejected maintaining parallel per-harness asset trees as a guaranteed divergence engine. The package identity dropped its harness prefix to become plain `dev-loops`, and every dev-loops-owned env var renamed `PI_*` to `DEVLOOPS_*` as a deliberate 0.x breaking change with no shims; we rejected keeping `PI_*` aliases or fallbacks, which would have preserved the coupling the rename existed to remove.

## Consequences

This is the largest external-coupling decision in the repo: one shared core runs behind per-harness adapters, so supporting a new harness means writing two adapter implementations rather than forking the runtime. Generate-don't-fork is now the asset model every skill, agent, and hook change must follow — edits land in the canonical sources and the committed `.claude` tree is regenerated, with the drift check keeping hand-edits out. Harness-agnosticism is enforced mechanically rather than by convention: the import-boundary and env-var contract tests turn any new Pi coupling outside the adapters into a test failure. The breaking rename cost every existing installation a migration but bought a neutral identity with no legacy alias surface to maintain. The adapter idiom proved out here became the house pattern for external coupling, later reused for the tracker seam.
