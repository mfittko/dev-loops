# 0022. Run exploratory spikes tracker-exempt under a relaxed gate profile, with discard or graduate-to-plan as the only exits

## Status

Accepted

## Context

Every dev-loop run assumed a tracked deliverable headed for the full production-gate ceremony, so exploratory, question-driven work — no issue, no code deliverable, outcome unknown — was either impossible to run inside the loop or absurdly over-gated. The spike-mode track ([issue 955](https://github.com/mfittko/dev-loops/issues/955)) shipped in three phases: [issue 964](https://github.com/mfittko/dev-loops/issues/964) / [PR 967](https://github.com/mfittko/dev-loops/pull/967) delivered the `--spike` entry and findings-artifact format, [issue 965](https://github.com/mfittko/dev-loops/issues/965) / [PR 970](https://github.com/mfittko/dev-loops/pull/970) the relaxed gate profile and the discard/graduate exits, and [issue 966](https://github.com/mfittko/dev-loops/issues/966) / [PR 986](https://github.com/mfittko/dev-loops/pull/986) the canonical contract (`skills/docs/spike-mode-contract.md`) with a worked example of both exits. The constraint throughout was that a sanctioned exploration modality must neither pollute the tracker nor dilute the production gates.

## Decision

We run spikes as a distinct modality started from a local question file via `--spike` (mutually exclusive with `--issue`/`--pr`/`--plan-file`), with no GitHub issue and no tracker mutation at entry; the path is exempt from the worktree-isolation guard because there is no issue to key a worktree on. The deliverable is a findings document with a fixed section contract — Question, Approach, Findings, Recommendation — validated fail-closed, and intake is a closed three-state machine (`spike_in_progress` / `spike_ready_for_exit` / `ambiguous_fail_closed` in `packages/core/src/loop/spike-intake-contract.mjs`) that deliberately does not reuse the plan-file intake states, because a spike classifies progress toward an exit decision, not toward promotion. The spike runs under `gates.spike` — angles `scope` and `docs` only, `required: false`, `requireCi: false` — resolved through the same config layering and `resolveGateConfig` path as the production profiles; we rejected a new strategy-to-knob resolver as unnecessary. Exactly two operator exits exist in `scripts/refine/exit-spike.mjs`, eligible only from `spike_ready_for_exit`: discard, which leaves zero tracker artifacts, or graduate, which emits a local-first plan file (via the pure `buildGraduatedPlanBody`) that enters the existing plan-to-PR promotion path and full gating. We rejected a tracker-backed spike outright — a spike is local by construction — and any third exit or ad-hoc gate skip.

## Consequences

Exploration gets a cheap sanctioned lane without weakening production gates: relaxation is scoped to the spike profile, which is optional in the schema and absent for non-spike work, and any code that ships still passes the normal plan-to-PR gate chain after graduation. The spike becomes the second gate-modality carve-out alongside light mode, both expressed as explicit gate profiles and config knobs rather than ad-hoc skips, which keeps future modality proposals on the same pattern. Graduation is idempotent and fails closed on an empty required section, so a graduate exit cannot emit a plan the plan-file validator would reject. The accepted cost is that discarded spikes leave no tracker residue by design — their history lives only in the local findings artifact, so an exploration's negative result is invisible to anyone without that file.
