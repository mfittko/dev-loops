# 0023. Default to local-first with a three-origin spec model; close tracker-first routing as won't-do

## Status

Accepted

## Context

The loop began tracker-first under the story-to-PR contract ([record 0003](0003-tracker-first-story-to-pr-contract.md), which this decision supersedes): every change minted a GitHub issue, went through refinement ceremony, and produced a phase doc, which proved heavyweight for small chores and spikes, and the work-origin contract required a `Closes #N` reference on every PR. Operating experience showed most work is better specified and reviewed locally before touching the tracker; the repo's own config led the flip by setting the default strategy to `local-first` (today the top-level `strategy` key) ([PR 743](https://github.com/mfittko/dev-loops/pull/743)) before the machinery existed to honor it fully. The Local-first P1–P6 series ([issues 949–954](https://github.com/mfittko/dev-loops/issues/949), landed as [PR 956](https://github.com/mfittko/dev-loops/pull/956), [PR 957](https://github.com/mfittko/dev-loops/pull/957), [PR 959](https://github.com/mfittko/dev-loops/pull/959), [PR 960](https://github.com/mfittko/dev-loops/pull/960), [PR 961](https://github.com/mfittko/dev-loops/pull/961), [PR 962](https://github.com/mfittko/dev-loops/pull/962)) built the plan-file path, and [issue 1033](https://github.com/mfittko/dev-loops/issues/1033) exposed that the built-in routing default still ignored the config, fixed by [PR 1038](https://github.com/mfittko/dev-loops/pull/1038). [Issue 1025](https://github.com/mfittko/dev-loops/issues/1025) asked for an even lighter path with no phase doc at all, delivered by [PR 1164](https://github.com/mfittko/dev-loops/pull/1164); [issue 1210](https://github.com/mfittko/dev-loops/issues/1210) extended it to issue-less PR-first via [PR 1215](https://github.com/mfittko/dev-loops/pull/1215), [PR 1350](https://github.com/mfittko/dev-loops/pull/1350) lifted the change-scope restriction behind config, and [PR 1242](https://github.com/mfittko/dev-loops/pull/1242) reconciled the contracts around three work origins. [PR 1403](https://github.com/mfittko/dev-loops/pull/1403) closed out the long-deferred `tracker_first` routed strategy as won't-do.

## Decision

We make local-first the default posture at every layer: the P-series delivers plan-file intake with a validated contract, off-tracker refinement with a human-review checkpoint, and PR-first promotion that commits the plan doc and opens one draft PR, and the startup resolver's built-in default routes to local-first rather than merely respecting a config override. An additive lightweight path makes the PR description itself the spec-of-record — `canonicalSpecSource: pr_body`, no phase doc — with `scripts/loop/validate-pr-body-spec.mjs` enforcing the spec invariants (objective, scope and non-goals, acceptance criteria, definition of done, risks) fail-closed with a distinct reason per violation. In issue-less mode the closing-issue reference flips from REQUIRED to FORBIDDEN: a PR that is the sole artifact must not carry a `Closes` reference to an issue that does not back it, so linkage state can never silently diverge. We initially restrict the issue-less path to small non-risky changes, then allow it at any change scope behind the boolean `localImplementation.issueless` rather than hard-coding a size heuristic. We reject a peer `tracker_first` routed strategy outright — tracker-backed work is an input source to the existing `local_implementation` strategy, not a separate routing family — and we reject keeping the option open indefinitely, closing it as won't-do so the strategy list stays honest.

## Consequences

Intake, gates, and validation all branch on one spec-source axis — `linked_issue`, `plan_file`, or `pr_body` — carried in the handoff envelope, and the same gate sequence applies regardless of origin; only the backing artifact differs. The PR body becomes a load-bearing artifact on the lightweight path, so body edits are spec edits and the fail-closed validator must gate them, which is stricter than the tracker-first world where the body merely pointed at the spec. The tracker-first detectors survive as standalone, directly-invoked tools that the startup resolver never dispatches to, an asymmetry this record exists to explain. Closing `tracker_first` as won't-do commits us to routing all future tracker-backed work through `local_implementation`'s input-source seam; reopening a routed tracker strategy would require a superseding record.
