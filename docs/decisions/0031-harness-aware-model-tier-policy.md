# 0031. Resolve the subagent model-tier policy per harness from config: routine work low, review and refinement high

## Status

Accepted — 2026-07-10 ([PR 1313](https://github.com/mfittko/dev-loops/pull/1313))

## Context

Which model tier a subagent ran on was informal operator policy — cheap models for routine implementation work, strong models for planning and critical review — living in operator memory and prompt conventions rather than anywhere the system could resolve mechanically, and with no per-harness answer at all for the Pi dispatch seam ([issue 1134](https://github.com/mfittko/dev-loops/issues/1134)). The `models` config already existed (`models.roles` concrete overrides, `models.conductor`), so the question was whether to grow it or invent a parallel tier block. The policy landed on 2026-07-10 via [PR 1313](https://github.com/mfittko/dev-loops/pull/1313); a follow-up the same day, [PR 1315](https://github.com/mfittko/dev-loops/pull/1315), fixed a silent downgrade where a gate review angle whose name collides with a routine role name (`docs`, the only collision) resolved low instead of high on the Pi seam. The mechanism lives in `packages/core/src/config/config.mjs` (`models.tiers`, `models.roleTiers`, `resolveRoleModel`) and `packages/core/src/claude/asset-generation.mjs`.

## Decision

We encode the tier policy in the existing `models` config rather than a parallel block: `models.tiers` maps tier aliases to per-harness model ids (`{ claude, pi }`, null = inherit), `models.roleTiers` maps roles and gate angles to tier aliases, and the exported `resolveRoleModel(config, { role, harness, kind })` is the single resolver, with precedence concrete `models.roles[role]` > tier alias > inherit. Built-in defaults reproduce the standing policy — `developer`/`docs`/`fixer`/`quality` → `low` (sonnet on Claude), `refiner`/`review` → `high` (opus on Claude), `dev-loop` → `inherit`, and all Pi tiers null so zero-config is a genuine no-op on Pi. Generated Claude agent assets get a `model:` frontmatter stamp from the resolver at generation time, so the committed `.claude` tree bakes the policy; Pi dispatch resolves at the seam with `kind: "angle"` forcing gate review angles to the review tier even when their name collides with a routine role. The schema fails closed: unknown tier aliases in `roleTiers` are rejected, and a tier mapping with no concrete harness model is invalid. We rejected persona-first disambiguation for the angle collision (provably insufficient — the `docs` angle maps to the `docs` persona, which is low), rejected routing that angle through the review persona (a larger persona-registry change), and rejected forcing routine gate angles low by default, which risks silent review-quality regression.

## Consequences

Which intelligence tier runs each role is now an architectural fact resolved per harness from config, and changing review economics is a config edit — one `tiers`/`roleTiers` entry — instead of a doc hunt through prompt conventions. Future model routing builds on this seam: any dispatcher asks `resolveRoleModel` rather than encoding tier knowledge itself, and the Claude side inherits the policy for free through baked frontmatter. The cost is a precedence surface callers must respect — gate-angle dispatch must pass the angle kind or a name collision silently downgrades the reviewer — and concrete alias values are operator-owned defaults that drift with model generations, so they need occasional retuning. Auto-tuning, per-model cost accounting, and a general routing framework were explicitly left out; if they arrive, they layer on this resolver rather than replacing it.
