# 0077. PRs record changelog notes as changeset fragments, assembled at release

## Status

Accepted — 2026-09-20 ([PR 2302](https://github.com/mfittko/dev-loops/pull/2302))

## Context

Every PR edited the shared `CHANGELOG.md` `## Unreleased` section to satisfy `LIFECYCLE-CHANGELOG-COMPLETENESS` (`skills/docs/pr-lifecycle-contract.md`). In a multi-PR drain, each PR after the first therefore CONFLICTS on `CHANGELOG.md` once a sibling merges. This repo does not require branches be up to date before merge, so once code files are distinct (distinctness gating already ensures that) the changelog was the SOLE recurring conflict source. Resolving it forces a base-move (merge `origin/main` into the branch), which triggers a full `pre_approval` re-gate and a Copilot re-request on nearly every merge — the base-move re-gate tax observed across #2286/#2287/#2291/#2288. [Issue 2293](https://github.com/mfittko/dev-loops/issues/2293) ordered the conflict trigger removed.

## Decision

Each PR records its changelog note as a NEW, uniquely named `changes/<slug>.md` fragment file instead of editing `CHANGELOG.md` directly. Uniquely named fragments never collide, so concurrent PRs stop conflicting on the changelog. The completeness gate (`scripts/docs/validate-changelog-completeness.mjs`) accepts a fragment in place of a direct `## Unreleased` edit; the legacy direct-edit path still passes (backward compatible, so historical content and in-flight `## Unreleased` entries are untouched). At release, `scripts/release/bump-version.mjs` assembles every pending fragment into `## Unreleased` via `scripts/release/assemble-changelog-fragments.mjs` (`assembleFragments`/`readFragments`), removes the consumed fragment files and stages their deletion, then stamps `## Unreleased` to `## <version>` exactly as before — the existing release stamp and `extract-changelog-section.mjs` guard are unchanged. `changes/README.md` documents the convention; `LIFECYCLE-CHANGELOG-COMPLETENESS` remains the canonical owner and now names the fragment path.

Rejected: keeping the direct `## Unreleased` edit and making the base-move cheaper instead (that is the complementary [issue 2292](https://github.com/mfittko/dev-loops/issues/2292) — this removes the conflict TRIGGER, that makes a base-move safe when one still happens); rewriting historical `CHANGELOG.md` content (out of scope, existing entries preserved); a structured multi-field fragment format (a plain Keep-a-Changelog bullet body is enough — the assembler concatenates fragment bodies under `## Unreleased`).

## Consequences

A drain of PRs touching distinct code files no longer hits a changelog conflict, so the base-move re-gate tax disappears for the common case. The gate accepts only a NEWLY ADDED, NON-EMPTY, REGULAR-FILE `changes/<slug>.md` fragment (base→HEAD `--diff-filter=A`, README excluded, empty/whitespace content rejected, symlinks rejected), so a modified/deleted existing fragment, a contentless fragment, or a symlink cannot satisfy the requirement. The gate and the release assembler apply the identical regular-file-only policy and never follow a symlink — neither a fragment file nor the `changes/` directory itself may be a symlink (both are `lstat`-checked) — so an untrusted PR cannot point a fragment, or the whole `changes/` directory, at arbitrary host files to leak (or, at release, delete) them via `CHANGELOG.md` assembly. Fragment bullet order within a release section follows the fragment filename sort, resolved once at release time. `changes/` accumulates one small file per unreleased PR; a release removes the consumed fragments. `bump-version` fails closed rather than writing a duplicate version heading whenever a `## <version>` section already exists and there is anything to stamp (pending fragments, or a live `## Unreleased` from the legacy direct-edit path — for example after a partial bump); the pure idempotent re-run (target stamped, no `## Unreleased`, no fragments) is still a no-op.
