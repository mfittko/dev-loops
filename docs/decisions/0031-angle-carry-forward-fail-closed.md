# 0031. Carry a clean gate angle forward across a head bump only when the delta provably misses its review surface

## Status

Accepted

## Context

`GATE-EXEC-REGATE-MANDATORY` forced a full fresh gate pass on every new head SHA, so a one-line fix commit re-fanned every reviewer even when most angles had provably nothing new to look at — an unbounded cost on iterative PRs, where each retry round bumps the head. The fix landed 2026-07-10 as a fail-closed carry-forward seam ([issue 1308](https://github.com/mfittko/dev-loops/issues/1308), [PR 1325](https://github.com/mfittko/dev-loops/pull/1325)), specified as rule `GATE-EXEC-ANGLE-CARRY-FORWARD` in `skills/docs/gate-review-sub-loop-contract.md` and implemented as the pure module `packages/core/src/loop/gate-carry-forward.mjs` behind the CLI `scripts/github/resolve-angle-carry-forward.mjs`. The same seam was immediately reused for the Copilot convergence carve-out, letting a pure doc/prose post-convergence bump skip a fresh blocking Copilot round ([PR 1329](https://github.com/mfittko/dev-loops/pull/1329)).

## Decision

We decide carry-forward with a pure deterministic seam — `resolveCarryForwardAngles` in `@dev-loops/core/loop/gate-carry-forward`, driven from the worktree at the new head — that computes the delta as the direct two-dot `git diff A..B` (never three-dot, which under a rebase or amend can omit a file that changed since the reviewed head), classifies each changed file by kind, and carries a previously-clean angle only when every changed file falls provably outside that angle's review surface, itself derived from the single-source `CATEGORY_ANGLE_MAP` so surfaces never drift from dynamic-angle rules. Every uncertain case fails closed to must-re-run: a non-clean or missing prior findings-log, an empty or unavailable delta, an unclassifiable file, an angle with no declared surface, a configured mandatory or always-run angle, and any rename in the delta (which forces the rename-implicated angles to re-run, since classifying only the destination path misses what the move itself implicates). Carried verdicts keep honest provenance — the new head's findings-log records `carriedFromHead` plus the prior head's full reviewer identity — so carry-forward never fabricates a reviewer or a fresh review. The seam's `resolveConvergenceCarryForward` companion drives the Copilot convergence decision from the same delta classification. We rejected orchestrator judgment about what changed: discretionary "this commit looks trivial" calls are exactly the non-reproducible guesswork the mandatory re-gate rule exists to prevent.

## Consequences

The mandatory-re-gate rule is re-scoped through a deterministic seam rather than softened by discretion: the full gate chain still runs at the new head (context-builder and consolidation always fresh, plus every touched or mandatory angle), and cost stays proportional to real change instead of commit count. The surface-mapping model is load-bearing for anyone adding angles — an angle without a mapped surface always re-runs, so a new angle pays full re-review cost until someone maps it, and mis-mapping a surface is the one way to skip a review that mattered. Provenance-consuming checks (distinct-reviewer counts, mandatory-angle consistency) work unchanged because carried entries carry real prior identities, not synthesized ones. Any future "skip this review" pressure now has a sanctioned answer: extend the seam's classification, never add an orchestrator escape hatch.
