# 0255. A reviewer-only pre-push delta clears a code range without a fixer plan

## Status

Accepted, 2026-11-05 ([issue 3122](https://github.com/mfittko/dev-loops/issues/3122), [issue 3105](https://github.com/mfittko/dev-loops/issues/3105)).

Amends the remedy of [ADR 0254](./0254-cap-chain-delta-extension.md). Every other decision of that record stays in force, and the record stays unedited.

## Context

ADR 0254 names a `locally_clear` pre-push delta for the start of the logic range as the remedy for a code commit past the cap round. The act-list delta needs a fixer plan and a coverage record bound to that baseline. Only a fixer emission creates them, and the emitter refuses a head other than the PR head. After a `head_moved` closure removes the sequence marker and supersedes the plan, no command re-creates the binding. Every base refresh moves the head, so the remedy worked only for a PR that never refreshed its base (issue 3122, PR 3087). The thread-route delta needs an unresolved review thread, which a PR may not have.

## Decision

1. `check-pre-push-delta.mjs --reviewer-only` opens an ACT delta sequence over `--baseline..--pr-head`. It requires `--findings-log <cap-round findings log>`, `--repo <owner/name>` and `--pr <n>`. The log must carry that repo and pr, and the pair is the target that lets the log of the cap round reach a chain-end baseline through the sealed clearing chain of that PR (the act-list route takes its target from the authenticated fixer plan, which this route has none of). `capRoundCovers` re-derives the act refs from the real ledger downstream. When the log's head is the baseline, the act list is derived from that ledger: the open act clusters, each with the cluster ref `capRoundActRefs` yields (`capRoundActList` and `capRoundActRefs` share one derivation), with no remediation scope fields. A clean cap round yields no item. When the log is an earlier head that the sealed clearing chain reaches, the list is empty because a chain link needs no covering. The worktree HEAD must equal `--pr-head` and the baseline must be an ancestor of it. The route refuses a worktree HEAD equal to the baseline, a range with no PR-own commit, an active sequence marker for the baseline, and a protected record at the baseline (decision 6). The invocation must be the prior record's invocation plus one (1 when none), so the bound of 3 counts those records. At the bound the route refuses `bounded_out`, `restart_on_replacement_pr`. The route refuses `--act-list`, `--threads-file`, `--fixer-plan`, `--site-coverage`, and `--handback`. It writes no sequence marker and keeps the stale-surface check.
2. The reviewer reads the whole range, marks each derived act item resolved, not_resolved or cannot_verify, and reports every finding. The result run seals `gate-delta/<baseline>.json` through the existing writer, in the existing record format, with `items` carrying exactly the derived refs. The record is `locally_clear` only when every item is resolved and the result has no medium-or-higher finding, so `capRoundCovers` passes for a non-clean cap round. A result with an open finding seals `needs_fix`, which `extend-cap-round-chain` does not accept. At invocation 3 an open finding seals `bounded_out` with `nextStep` `restart_on_replacement_pr`, never `push_to_gate`, so the route writes no clearing step. A non-clearing result never replaces a `locally_clear` record, and no result replaces one that carries an extension.
3. A merge in the range that `origin/<base>` does not hold must pass `isBaseOnlyMergeSince` from its first parent. The changed-files list comes from the PR-own commits (`git log --no-merges ... ^origin/<base>`). The reviewer patch and the stale-surface scan are the cumulative `git diff baseline..head` limited to those paths, so a base refresh adds no files for the reviewer. A merge that is not base-only (a merge of a branch with PR-own commits, a conflict resolution, an evil merge) is reviewed through its PR-own commits and its resolution diff: `git show --remerge-diff` (the merge against an automatic remerge of its parents) names the paths the merge changed by hand, and those paths join the PR-own paths, so the cumulative patch holds them. An octopus merge, or a merge whose resolution diff git cannot read, makes the route refuse `non_base_only_merge`, naming the merge. Only the replacement-PR restart remains for that PR.
4. `gate extend-cap-round-chain` is unchanged. It reads the sealed record as the covering delta and seals `extension: "delta_covered"`, as ADR 0254 decision 1 describes, over a range that includes a base-only merge.
5. The remedy of ADR 0254 decision 2 is: run the pre-push delta for the start of the logic range (the act-list delta for a fixer pass, the thread-route delta or the reviewer-only delta otherwise) until `locally_clear`, then rerun the command. The rule `GATE-EXEC-ROUND-CAP-CHAIN-EXTEND` in `skills/docs/gate-review-sub-loop-contract.md` records the behavior.

## Consequences

A PR whose head moved after a closed sequence reaches a covering record with one reviewer run and no plan. The route trusts the reviewer's report of the range, the same as the thread route does for its threads. The act-list route and its coverage binding are unchanged for an open sequence. The remedy sentences inside the `extend-cap-round-chain` refusal texts, the cap-round refusals of `pr-gate-coordination` and the reviewer-only refusals name the reviewer-only route and only commands that exist in the CLI registry.

## Amendment: the replay of PR 3087 (issue 3122)

6. A record at the baseline is protected unless it is the same act set (the same `actSetId`), or all of these hold: it is non-clearing (not `locally_clear`), it carries no extension, its `items[].ref` set equals the derived refs, and its `candidateHead` is an ancestor of the PR head. A record that passes the second set is taken over: the fixer's `needs_fix` record of PR 3087 (invocation 1, 10 refs, another `actSetId`) blocked the route with a refusal that no command could clear. The run continues its invocation number (prior 1 makes this run 2, and the bound of 3 holds) and the result run replaces it. A `locally_clear` record for another act set, a record with an extension, a record with another ref set and a record whose candidate is off the PR head's history stay protected and are never overwritten.
7. An unsealed record at the baseline follows the same rules, because a crash between the record write and its seal leaves an unsealed pair. The route reads the record without the seal and applies decision 6 to its content, so a passing unsealed record is taken over and the result run reseals. An unsealed record that fails decision 6 refuses `unsealed_record` with the remedy `rm -f <record> <record>.seal` and a rerun, which restarts the invocation count. The refusal is fail-closed: the content of an unsealed file is never evidence, and the route never reseals it unchanged.
8. The cap-round refusals are typed: `baseline_orphaned` and `cap_round_unresolved` name the operator (`blockedOn` `operator_decision`) because no command clears them, and `unsealed_record` routes to `gate extend-cap-round-chain` like the three conditions of ADR 0254. The draft-round-cap entry of `KNOWN_GAPS` is removed. The conformance walk checks that every cap-round block is typed, that its command parses on the extension route, and that every command named in the three tools' remedy texts exists in `SUBCOMMAND_ROUTES`.

9. A round 1 gate review of the pull request amended three details. The result run recomputes the cumulative patch and refuses when it differs from the patch the input run wrote, so a moved `origin/<base>` cannot change the PR-own path set between the reviewer's read and the verdict. The result run writes the record under `withSequenceLock` for the baseline and refuses when the record differs from the snapshot every check judged (a concurrent run or `extend-cap-round-chain`). A record that is not JSON, or a candidate that is not in the clone, refuses `unsealed_record` or the protected-record reason with the same `rm -f` remedy.

## Closed and remaining dead ends

Closed by ADR 0254, ADR 0255 and this amendment, each proven by `test/loop/cap-round-no-dead-end.test.mjs` (the matrix over cap round shape, sequence state, base refreshes and later commits) and the replay of PR 3087:

| Condition | Closed by |
| --- | --- |
| `no_clearing_record`, `no_cap_round_chain` after a head move | The reviewer-only record at the cap-round head (decision 1, 2) |
| `items_do_not_cover` for a non-clean cap round | Record `items` carry the derived refs, all `resolved` |
| `logic_commit_in_range`, `delta_range_mismatch` | A `locally_clear` reviewer-only record for the start of the logic range, then `extend-cap-round-chain` |
| `record_not_clearing`, a fixer `needs_fix` record with another `actSetId` | The take-over (decision 6) |
| `unsealed_record` with a passing content | The take-over (decision 7) |
| `logic_commit_in_range` for a second logic commit after a `delta_covered` extension | The reviewer-only delta at the chain end as baseline, with `--repo` and `--pr` (decision 1; `test/loop/cap-round-no-dead-end.test.mjs`) |
| `non_base_only_merge` for a merge of PR-own work or a conflict resolution | The resolution-diff review (decision 3) |

Remaining, with the exact remedy for each:

| Condition | Why it remains | Remedy |
| --- | --- | --- |
| `baseline_orphaned` | A rebase removed the cap-round head from the history | The replacement-PR restart: `node <dev-loops-package-root>/cli/index.mjs pr create --head <new-branch> --allow-replacement-pr <this PR number>` (the full sequence is `CAP_ROUND_REFUSAL.baseline_orphaned`); the operator decides |
| `cap_round_unresolved` | An unreadable ledger or config | Repair or quarantine the file under the gate tmp root, then `node <dev-loops-package-root>/cli/index.mjs loop gate-coordination --repo <owner/name> --pr <n>`; the operator decides |
| Bound 3 with an open finding | The reviewer still reports a finding at invocation 3 | The replacement-PR restart (`bounded_out`, `restart_on_replacement_pr`) |
| Active sequence marker for the baseline | An open sequence belongs to the fixer | The fixer closes it by pushing its commit; an abandoned one: `node <dev-loops-package-root>/cli/index.mjs gate close-sequence --head <baseline> --repo <owner/name> --pr <n>` |
| Head equal to the baseline, or no PR-own commit, with open act items | There is nothing to review and the act items need a fixer commit | `node <dev-loops-package-root>/cli/index.mjs loop gate-coordination --repo <owner/name> --pr <n>` for the fixer step |
| A clean cap round with a `needs_fix` record at the cap-round head and only a docs or tests commit after it | The take-over seals `locally_clear` with no extension, and `extend-cap-round-chain` refuses `chain_reaches_head` for a chain that ends at the head. | `unsealed_record` whose content fails decision 6 | Its content is not evidence | `rm -f <record> <record>.seal` and rerun, as the refusal prints |

One limit of the review stays: the cumulative patch of a path that both the PR and the base changed holds the base-side lines of that path, so the reviewer reads them. The stale-surface scan of such a path can report hits from base-side removals, and the reviewer names each in a finding or a skipped site.
