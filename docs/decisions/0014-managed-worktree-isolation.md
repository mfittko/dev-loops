# 0014. Run local implementation only in managed, namespaced worktrees behind a mechanical pre-flight gate

## Status

Accepted

## Context

Local implementation runs mutated the main checkout directly — an agent created a working branch with `git checkout -b` on `main` despite the documented worktree mandate — colliding with parallel runners and the operator's working tree and risking direct-main commits ([issue 497](https://github.com/mfittko/dev-loops/issues/497), fixed by [PR 501](https://github.com/mfittko/dev-loops/pull/501)). Worktree creation, naming, and cleanup were fully manual: paths were unpredictable (a branch suffix made them unrecomputable from the issue number), stale worktrees accumulated, and destructive cleanup could not tell loop-owned worktrees from hand-made ones ([issue 909](https://github.com/mfittko/dev-loops/issues/909), [PR 915](https://github.com/mfittko/dev-loops/pull/915)). Fresh worktrees created without fetching first branched off stale bases ([PR 574](https://github.com/mfittko/dev-loops/pull/574)), and raw `git worktree add` left them unprovisioned — Node's upward walk silently resolved `@dev-loops/core` to the main checkout's copy, so tests exercised the wrong code ([PR 1178](https://github.com/mfittko/dev-loops/pull/1178), recurring as [issue 1432](https://github.com/mfittko/dev-loops/issues/1432)). Because every worktree shares one `.git` directory, `refs/stash` is a single ref across all of them, and parallel agents popped each other's stashes ([issue 1406](https://github.com/mfittko/dev-loops/issues/1406), [PR 1410](https://github.com/mfittko/dev-loops/pull/1410)).

## Decision

`local_implementation` may only run inside a managed worktree at the namespaced path `tmp/worktrees/dev-loops/<kind>-<number>`, recomputable from the issue/PR number alone via the single shared resolver (`resolveWorktreePath`). A fail-closed pre-flight gate (`scripts/loop/pre-flight-gate.mjs`) verifies worktree isolation and branch identity before any mutation, and the startup resolver rejects `local_implementation` routing from the main checkout — we rejected the prior doc-only mandate because AGENTS.md prose demonstrably failed to prevent violations. The lifecycle is fully tool-owned: `ensure-worktree.mjs` is the sole sanctioned create-plus-provision entrypoint (idempotent, fetches the base remote first, and applies `.devloops`-configured provisioning including the `@dev-loops/core` workspace link — a targeted symlink chosen over a per-worktree `npm install`, which was rejected as too heavy). Cleanup (`cleanup-worktree.mjs`) resolves paths through the same resolver and never touches anything outside `tmp/worktrees/dev-loops/`. `git stash` is forbidden repo-wide and blocked at the tool gate, since the shared-`.git` layout makes `refs/stash` cross-worktree state; agents use `git diff` patch files or a scratch worktree instead.

## Consequences

The namespace makes destructive cleanup provably safe: it can only ever remove worktrees it owns, so a hand-made `tmp/worktrees/my-experiment` is never touched. Parallel-runner dispatch, resume, and path resolution all assume the recomputable layout — any component can derive the worktree path from the issue/PR number without stored state. Raw `git worktree` commands in agent flows are contract breaches, because bypassing the entrypoint recreates the silent-wrong-core failure mode the provisioning step exists to prevent. The price is that every local run pays provisioning overhead through one entrypoint, and the gate adds a mandatory step-zero check before any edit; a documented fail-open fallback (dedicated branch in the current checkout) remains for environments where worktrees are unavailable.
