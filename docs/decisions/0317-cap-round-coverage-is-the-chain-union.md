# 0317. Cap-round coverage is the union of the clearing chain's records

## Status

Accepted — 2026-11-22 ([issue 3443](https://github.com/mfittko/dev-loops/issues/3443)). Amends ADR 0208, ADR 0224, ADR 0255 and ADR 0313 (the `no_cap_round_chain` recovery for a non-covering sealed record).

## Context

A cap round with three act items had one item escalated under `GATE-EXEC-RECURRENCE-ESCALATION`. The operator chose to fix it in the PR. The commit_only fixer record covered the two other act refs. A fixer and a delta review then fixed the escalated item against a later baseline and sealed a second `locally_clear` record, which named a thread id and no act ref. `capRoundCovers` read only the first record of the chain, so the proof refused `items_do_not_cover` and the only exit was a replacement PR.

## Decision

- `capRoundCovers` accepts a non-clean cap round when the union of the `items` refs of every sealed clearing record on the chain that starts at the first record names every act ref. One helper (`capRoundCoverage`) computes the union and returns the uncovered refs and the records read. One async helper (`capRoundChainCoverage`) reads the starts and returns the coverage of the start with the fewest uncovered refs: the proof, `extend-cap-round-chain` and the reviewer-only refusal all use it.
- Each link's baseline is the previous link's candidate head or a proven base-only merge of it (the bridge below), so every baseline is an ancestor of the head the chain reaches or of that merge. The proof still requires the chain to reach the head.
- The union spans only the links the proof traverses. The walk stops after the link whose candidate is the PR head, so a sealed link past the head covers nothing. Under `anyHead` a link after the first counts only when its candidate is an ancestor of the head. A link after the first counts only its items with status `resolved`, because a `bounded_out` record can carry unresolved items. The union therefore reads sealed clearing records of any outcome (`locally_clear` and `bounded_out` with a clearing next step) and counts only resolved items on a later link.
- The union crosses the seeded link from a chain end to its proven base-only merge (the `bridges` that `capRoundChainStarts` returns). A record on the far side of a base-only merge of a chain end joins the chain as a link; a record behind a merge that is not base-only joins nothing, and an unresolved item counts for nothing. A bridged record is never a start of its own, because a start counts every item of its first record. With several sealed merge records of one chain end, `bridges` holds one choice each and the proof and the extension tool try each choice in SHA order, so a stale record does not hide a covering one while the combinations stay within the limit of 16: `capRoundChainStarts` keeps the first 16 combinations in SHA order and drops the rest, so a round with more combinations can refuse `items_do_not_cover` although a dropped combination covers it (the proof fails closed; the limit is not raised). The proof's `reaches`, `capRoundCoverage` and the chain-end walk follow the same link, and a head that is a base-only merge of a chain end is reached through the base-only check before a bridge is followed, so a bridge never takes the proof past the head. The coverage walk stops at the same link (a draft PR whose head is a base-only merge of a chain end counts no bridged record past it), and a clean cap round follows the bridge to find its extension and stops there too, never goes past the PR head and, under `anyHead`, counts the extension of a later link (direct or bridged) only when its candidate is on the head's history (an unreadable candidate fails closed). A candidate that the stop priming never probed (a link rewritten between the priming and the read) reads as a stop, so the coverage walk fails closed rather than cross a bridge the proof may stop at.
- The proof judges the coverage and the reachability of each start on one snapshot of its chain (each link is read once), so a record rewritten during a probe cannot prove a round that no single chain state proves.
- Only `git merge-base --is-ancestor` exit 1 without a signal proves a candidate off the head's history. Any other failure (exit 128 for a commit this clone never fetched, a signal, a spawn error) is an unresolved history: the proof still fails closed, but the detail names `git -C <checkout> fetch origin <sha>` (the repository the check read, carried as `detail.checkout`, so the command acts on it and never on the caller's cwd; the tools name their resolved worktree the same way) for the commit this clone lacks (the PR head included, never a present candidate) and lists no ref as uncovered, `extend-cap-round-chain` returns `history_unresolved` with the fetch as its recovery in place of the replacement PR, and the reviewer-only and cover runs ask for the same fetch, also for the prior record's own candidate when that record is sealed. An unsealed prior record keeps its `unsealed_record` refusal with its fetch hint and its `rm -f` remedy (its candidate is never read as evidence), so a candidate absent from the clone never hides the remedy. The replacement PR is named as the next exit for a commit that stays absent after the fetch.
- The `extend-cap-round-chain` `no_cap_round_chain` refusal for a non-covering sealed record names the uncovered act refs and the records that exist. A reviewer-only run with a chain-end baseline derives an empty act list (ADR 0255) and covers no act ref, so it is not the recovery for an uncovered ref.
- Amends ADR 0255 with the cover run (operator decision, 2026-11-22): `loop pre-push-delta --reviewer-only --cover-uncovered` takes the cap-round head as baseline and reviews the cap-round head..PR head diff with no new commit. Its act list is only the cap round's act entries that no record on the chain and no sealed cover record names. A fresh reviewer verifies those refs, and every result run seals one cover record per verified ref under `gate-cover/`, keyed by the cap-round head and the ref, with the capped `findings` that a gate-delta record seals (a lifecycle refusal first, then the reviewer's findings, at most 20) so a refused cover run names its cause (`PRE-PUSH-DELTA-EXIT-BOUND`); the stdout of the run prints the same list. Coverage counts a cover record that is sealed, `locally_clear`, `resolved` and whose candidate is the head or on its history. The run takes no baseline record slot, reads no thread text and fails closed. It never overwrites a gate-delta record, and it never replaces a cover record that is clearing, unsealed, unreadable or at the last invocation; the next invocation supersedes only its own sealed non-clearing cover record below the bound. It refuses a clean cap round, a baseline other than the cap-round head, a cap round with no sealed clearing chain start (a record at the cap-round head or at a proven base-only merge of it) and a round whose refs are all covered, each with a rendered recovery that names real arguments (the extension command, the cover run at the cap-round head or the plain reviewer-only run, with the resolved worktree and the canonical ledger so it runs from any caller directory). The refusal for a non-covering sealed record names the cover run first and the replacement PR as the alternative, only while the record's candidate is on the head's history, every uncovered ref's cover record can take another run and, on a draft PR, some sealed clearing chain visits the head or ends on its history (a chain A..H followed by a sealed H..X visits H, so it reaches the head whatever a later record covers): the draft proof still needs a chain that reaches the head, so a cover run over a chain that never visits the head and whose every end is off that history ends in the same replacement PR. A ready PR keeps the cover run, because its `anyHead` proof accepts the first record whatever its candidate: the cover run, the extension tool and the reviewer-only refusals apply that one candidate rule, so a ready PR whose first candidate git proves off the history still gets the cover run (or the extension command when every ref is covered), a draft PR gets the replacement PR and an unreadable history gets the fetch. On a ready PR the extension tool still runs the docs, tests and `delta_covered` seal for an available chain end first (the waiver and the fixer emitter name it for that), and returns `already_proven` by the `anyHead` proof that coordination uses only where it would otherwise refuse. The ready-PR candidate rule at the invocation bound does not apply to a clean cap round, because the `anyHead` proof needs an extension there. An unreadable draft state reads as a draft. The extension tool reads the cover records once under the cap-round head's sequence lock. Every caller scans the chain starts, the bridges and the reachability before it takes a lock and, under the lock, reads again only the linked records and the cover records from that scanned chain (the coverage rereads run no directory scan or base-only probe while a lock is held, so a scan cannot outlast the lock wait; the extension seal paths still run the proof under their sequence lock, and that proof scans the store and probes base-only merges when the direct chain does not prove the round); the plain run, the cover run and the extension tool reread the coverage that way, and a cover run or extension that sees a different uncovered set under the lock (or a first covering read that covered no start while the second read covers every ref) writes nothing and returns the rerun (`record_changed` for the extension tool). The plain run also compares the start records (the cap-round head's and each scanned merge's) under the lock with the scan and returns the input-run rerun when one differs, because a start sealed after the scan reads as no coverage. A covered round whose first proof failed gets the proof again (a cover run that completed after it makes a chain that ends at the head provable: `already_proven`). A history that becomes unresolved under the lock names the fetch before any blocker refusal in the cover run and the extension tool, and the plain run names it before `bounded_out` for a locally_clear record at the last invocation, which follows the one candidate rule (a ready PR keeps the chain-end command). A clean cap round whose sealed chain ends only off the head's history names the replacement PR (the record at the cap-round head is never overwritten, so `record_exists` would route back to the extension tool). The reviewer-only refusal at the cap-round head names the chain-end command when the union covers, the cover run when a readable coverage leaves a ref uncovered and the cover run can proceed (the conditions above, with every uncovered ref's cover record read under the existing sequence lock) and the replacement PR when the record's candidate is off the head's history on a draft PR, a cover record is a dead end, a draft chain cannot reach the head or the cap round is clean. The cover run takes the baseline's sequence lock, refuses an active sequence marker at the cap-round head (at the input run and the result run), snapshots every cover record of the run in its first locked read (the result run takes its own snapshot; the evidence run pointer and invocation checks bound a change between the two runs) and, under the lock of the write, refuses and writes nothing when a record or the next invocation differs from the snapshot (a concurrent cover run), with the input-run rerun as the recovery. A cover record that can take no further run is a dead end that refuses with the replacement PR and is never overwritten: a sealed `locally_clear` record whose candidate left the head's history, an unsealed, hand-edited or unreadable record (neither counted nor replaced, so it never restarts the bound) and a sealed record that used the last invocation. The cover record is a third exception to `PRE-PUSH-DELTA-NOT-GATE-EVIDENCE` under the same seal rule, read only by `readSealedCoverRecord`.
- An act-list delta record whose item `ref` is the ledger fingerprint also counts, as before. A thread-route delta item carries the threadId as its `ref`, and thread text is never trusted, so a thread-route record maps to no act ref and covers none. The union reads each item `ref` as written.
- `extend-cap-round-chain` passes the same history bound as `resolveCapRoundFixed` under `anyHead` (a later link counts only when its candidate is on the head's history, and a candidate that is not a full hex SHA is off the history without reaching git), so the tool and the proof cannot disagree.
- The coverage detail names the start with the fewest uncovered refs, and renders a missing SHA as `?`.
- Amends ADR 0313 for `head_mismatch`, which returns three recoveries, not the two named in ADR 0313: the fast-forward pull (worktree on the PR branch, HEAD an ancestor of the PR head or the PR head absent locally), the operator form for an ahead or diverged HEAD on the PR branch (push the local commits to the PR branch, or reset the worktree), and the operator form for another branch or a detached HEAD (check out the PR branch in a worktree and rerun with `--worktree`).
- Existing gate-delta records are never overwritten. The cover-record exceptions are listed in the cover run bullet. The round cap and the escalation rule are unchanged.

## Consequences

An escalated cap-round item that the operator fixes in the PR needs no replacement PR when a cover record of its act ref exists (the cover run) or an act-list delta record keyed by its act ref exists. A thread-route record names its items by thread id, thread text is never trusted to map a thread to an act ref, so a thread-route record covers no act ref, so the cover run covers that ref. A cap round with a genuinely uncovered act ref still refuses and names it, and a history that git cannot read names the fetch and no uncovered ref.
