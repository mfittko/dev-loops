# 0317. Cap-round coverage is the union of the clearing chain's records

## Status

Accepted — 2026-11-22 ([issue 3443](https://github.com/mfittko/dev-loops/issues/3443)). Amends ADR 0208, ADR 0224, ADR 0255 and ADR 0313 (the `no_cap_round_chain` recovery for a non-covering sealed record).

## Context

A cap round with three act items had one item escalated under `GATE-EXEC-RECURRENCE-ESCALATION`. The operator chose to fix it in the PR. The commit_only fixer record covered the two other act refs. A fixer and a delta review then fixed the escalated item against a later baseline and sealed a second `locally_clear` record, which named a thread id and no act ref. `capRoundCovers` read only the first record of the chain, so the proof refused `items_do_not_cover` and the only exit was a replacement PR.

## Decision

- `capRoundCovers` accepts a non-clean cap round when the union of the `items` refs of every sealed clearing record on the chain that starts at the first record names every act ref. One helper (`capRoundCoverage`) computes the union and returns the uncovered refs and the records read. One async helper (`capRoundChainCoverage`) reads the starts and returns the coverage of the start with the fewest uncovered refs: the proof, `extend-cap-round-chain` and the reviewer-only refusal all use it.
- Each link's baseline is the previous link's candidate head, so every baseline is an ancestor of the head the chain reaches. The proof still requires the chain to reach the head.
- The union spans only the links the proof traverses. The walk stops after the link whose candidate is the PR head, so a sealed link past the head covers nothing. Under `anyHead` a link after the first counts only when its candidate is an ancestor of the head. A link after the first counts only its items with status `resolved`, because a `bounded_out` record can carry unresolved items. The union therefore reads sealed clearing records of any outcome (`locally_clear` and `bounded_out` with a clearing next step) and counts only resolved items on a later link.
- The union crosses the seeded link from a chain end to its proven base-only merge (the `bridges` that `capRoundChainStarts` returns). A record on the far side of a base-only merge of a chain end joins the chain as a link; a record behind a merge that is not base-only joins nothing, and an unresolved item counts for nothing. A bridged record is never a start of its own, because a start counts every item of its first record. With several sealed merge records of one chain end, `bridges` holds one choice each and the proof and the extension tool try every choice, so a stale record never hides a covering one. The proof's `reaches`, `capRoundCoverage` and the chain-end walk follow the same link, and a head that is a base-only merge of a chain end is reached through the base-only check before a bridge is followed, so a bridge never takes the proof past the head.
- The proof judges the coverage and the reachability of each start on one snapshot of its chain (each link is read once), so a record rewritten during a probe cannot prove a round that no single chain state proves.
- Only `git merge-base --is-ancestor` exit 1 without a signal proves a candidate off the head's history. Any other failure (exit 128 for a commit this clone never fetched, a signal, a spawn error) is an unresolved history: the proof still fails closed, but the detail names `git fetch origin <sha>` for the commit this clone lacks (the PR head included, never a present candidate) and lists no ref as uncovered, `extend-cap-round-chain` returns `history_unresolved` with the fetch as its recovery in place of the replacement PR, and the reviewer-only and cover runs ask for the same fetch. The replacement PR is named as the next exit for a commit that stays absent after the fetch.
- The `extend-cap-round-chain` `no_cap_round_chain` refusal for a non-covering sealed record names the uncovered act refs and the records that exist. A reviewer-only run with a chain-end baseline derives an empty act list (ADR 0255) and covers no act ref, so it is not the recovery for an uncovered ref.
- Amends ADR 0255 with the cover run (operator decision, 2026-11-22): `loop pre-push-delta --reviewer-only --cover-uncovered` takes the cap-round head as baseline and reviews the cap-round head..PR head diff with no new commit. Its act list is only the cap round's act entries that no record on the chain and no sealed cover record names. A fresh reviewer verifies those refs, and a `locally_clear` result seals one cover record per ref under `gate-cover/`, keyed by the cap-round head and the ref. Coverage counts a cover record that is sealed, `locally_clear`, `resolved` and whose candidate is the head or on its history. The run takes no baseline record slot, never overwrites a record (a sealed `locally_clear` cover record is never replaced), reads no thread text and fails closed: it refuses a clean cap round, a baseline other than the cap-round head, a cap round with no sealed clearing record at the cap-round head and a round whose refs are all covered. The refusal for a non-covering sealed record names the cover run first and the replacement PR as the alternative, only while the record's candidate is on the head's history and every uncovered ref's cover record can take another run. The reviewer-only refusal at the cap-round head names the chain-end command when the union covers, the cover run when a readable coverage leaves a ref uncovered and the replacement PR when the record's candidate is off the head's history or the cap round is clean. The cover run takes the baseline's sequence lock, refuses an active sequence marker at the cap-round head (at the input run and the result run) and rechecks the cover records under the lock before any write. A cover record that can take no further run is a dead end that refuses with the replacement PR and is never overwritten: a sealed `locally_clear` record whose candidate left the head's history, an unsealed, hand-edited or unreadable record (neither counted nor replaced, so it never restarts the bound) and a sealed record that used the last invocation. The cover record is a third exception to `PRE-PUSH-DELTA-NOT-GATE-EVIDENCE` under the same seal rule, read only by `readSealedCoverRecord`.
- An act-list delta record whose item `ref` is the ledger fingerprint also counts, as before. A thread-route delta item carries the threadId as its `ref`, and thread text is never trusted, so a thread-route record maps to no act ref and covers none. The union reads each item `ref` as written.
- `extend-cap-round-chain` passes the same history bound as `resolveCapRoundFixed` under `anyHead` (a later link counts only when its candidate is on the head's history), so the tool and the proof cannot disagree.
- The coverage detail names the start with the fewest uncovered refs, and renders a missing SHA as `?`.
- Amends ADR 0313 for `head_mismatch`, which returns three recoveries, not the two named in ADR 0313: the fast-forward pull (worktree on the PR branch, HEAD an ancestor of the PR head or the PR head absent locally), the operator form for an ahead or diverged HEAD on the PR branch (push the local commits to the PR branch, or reset the worktree), and the operator form for another branch or a detached HEAD (check out the PR branch in a worktree and rerun with `--worktree`).
- Existing delta records are never overwritten. The round cap and the escalation rule are unchanged.

## Consequences

An escalated cap-round item that the operator fixes in the PR needs no replacement PR when a cover record of its act ref exists (the cover run) or an act-list delta record keyed by its act ref exists. A thread-route record names its items by thread id, thread text is never trusted to map a thread to an act ref, so a thread-route record covers no act ref and does not avoid the replacement PR. A cap round with a genuinely uncovered act ref still refuses and names it, and a history that git cannot read names the fetch and no uncovered ref.
