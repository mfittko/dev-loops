# 0024. Make the GitHub Projects board the queue, with Next Up as the sole fail-closed pickup source and refinement required at enqueue

## Status

Accepted

## Context

Queue pickup originally mixed local queue ordering, Backlog scans, and board state, so what the driver picked next was nondeterministic, un-prioritized or un-refined items could be auto-picked, and the operator's board prioritization did not reliably control autonomous runs ([issue 1091](https://github.com/mfittko/dev-loops/issues/1091)); the configured board was not even the membership source, silently no-oping on an empty local queue ([issue 864](https://github.com/mfittko/dev-loops/issues/864)). The board contract was first documented ([PR 641](https://github.com/mfittko/dev-loops/pull/641)), then the board became the queue membership source ([PR 884](https://github.com/mfittko/dev-loops/pull/884)), and `/continue` gained board-or-target dual routing ([issue 988](https://github.com/mfittko/dev-loops/issues/988), [PR 1004](https://github.com/mfittko/dev-loops/pull/1004)). Next Up became the normative fail-closed pickup source on 2026-07-02 ([PR 1097](https://github.com/mfittko/dev-loops/pull/1097)), with board Status transitions made deterministic shortly after ([PR 1115](https://github.com/mfittko/dev-loops/pull/1115)). Un-refined items still failed only much later at the draft gate, wasting full pickup cycles ([issue 1251](https://github.com/mfittko/dev-loops/issues/1251)), so the refinement check moved left to the enqueue choke point ([PR 1254](https://github.com/mfittko/dev-loops/pull/1254)). Continuous board reconciliation was then made a normative conductor responsibility ([PR 1269](https://github.com/mfittko/dev-loops/pull/1269)), and pickup later gained single-contributor ownership claims on top of these semantics ([PR 1378](https://github.com/mfittko/dev-loops/pull/1378)); the canonical rules live in `skills/docs/projects-queue-contract.md` and the enqueue gate in `scripts/projects/add-queue-item.mjs`.

## Decision

We make a configured, mandatorily repo-linked GitHub Projects V2 board the queue membership and ordering source, while GitHub issue/PR state remains the source of truth over the board — board state is a scheduling input, never a second truth. The driver auto-picks only from the Next Up column by position ascending: an empty Next Up fails closed to idle ("queue empty — prioritize Backlog items into Next Up") and a board-query error surfaces and stops the run; neither case ever falls back to Backlog or local queue order, because an outage must never silently drain Backlog. We rejected the soft-hint alternative where the board merely reorders a locally-owned queue: Backlog is unprioritized intake with no scheduling meaning, and promoting an item into Next Up is the deliberate prioritization step. Explicit single-issue/PR targets bypass this gating entirely — they route through the dev-loop path, not the queue driver — and board Status transitions couple deterministically to loop state rather than drifting on best effort. Finally, no un-refined issue may enter Next Up: the enqueue choke point requires the same refinement artifact the draft gate checks (acceptance criteria, DoD, or a linked refinement doc), failing closed interactively with `MISSING_REFINEMENT_ARTIFACT` and, in headless mode, diverting the issue to a non-pickup park column instead of failing the run. The draft gate stays as the unconditional backstop for anything that slips through another enqueue path.

## Consequences

Human prioritization is now the hard boundary on autonomous work selection: the driver deliberately trades availability for operator control, idling on an empty Next Up instead of inventing work. Un-refined items are rejected at enqueue rather than a full pickup cycle later, and a misconfigured or unreachable board halts runs loudly rather than degrading into local ordering. The conductor carries an ongoing obligation to keep the board reconciled with actual issue/PR state through the canonical projects scripts, since column names and the four-column vocabulary are a hard contract that tooling fails closed on. Conductor routing, enqueue tooling, board sync, and parallel-runner dispatch all build against these pickup semantics, so changing them means changing the contract first.
