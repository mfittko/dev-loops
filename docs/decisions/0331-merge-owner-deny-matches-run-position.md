# 0331. The merge owner deny matches the run position, not the raw text

## Status

Accepted — 2026-11-26 ([issue 3605](https://github.com/mfittko/dev-loops/issues/3605)).

Amends [0297](./0297-subagent-may-run-merge-test-files.md) for the match. ADR 0297 stays unedited.

## Context

ADR 0297 denies a subagent any Bash command whose raw text names the merge script. A read-only command matched too: `grep`, `sed -n`, `git grep` and `git show` of a path that holds the name, and `git show` of the ADR files 0249 and 0297. On 2026-11-26 the deny stopped the issue 3599 pull request four times, and one draft_gate review unit lost all five angles. Reading the file merges nothing.

## Decision

`decideMergePrOwnerDeny` denies a subagent command that runs the merge script. `scriptInvocationRe(basename)` builds the run-position matcher. The unresolve owner rule and the merge owner rule both use it. The run forms are `node <path>`, `bun <path>`, `dev-loops-run [--repo-root <p>] <path>` and the path as the command head, each at the start of the command or after `;`, `&&`, `||`, `|`, `(`, a backtick or a newline, and each with `--check`. The match still strips every quote character and backslash first, as the old raw-text match did, so `merge-""pr`, `merge\-pr` and `merge-"pr".mjs` stay denied and no quote pairing exists for an escaped quote to flip. The exact basename never matches a `.test.mjs` path, so the test-file exemption and `commandMentionsMergePr` are deleted. The role null path is unchanged.

## Consequences

A subagent reads the merge script, its callers and its ADRs with `grep`, `git grep`, `sed -n` and `git show`. The `node`, `bun`, `dev-loops-run` and command-head run forms stay denied, with or without the `.mjs` extension (`bun scripts/github/<stem>`). A `.test.mjs` path or a name with a suffix after the stem never matches. A name with a prefix before the stem still matches and is denied. `bun test <stem>`, with the bare stem as a test-name filter, stays denied; the full test path `bun test test/github/<stem>.test.mjs` runs. The matcher strips every quote character and backslash, so a quoted run path, a quoted launcher word (`'node' <path>`), a non-empty quote split of the name (`merge-"pr".mjs`, `'merge'-pr.mjs`) and an escaped or ANSI-C quote (`echo $'a\'b'; <path>`) all stay denied. A quoted search pattern that holds a separator and the name, such as `rg "foo|<name>.mjs"` or `grep -nE "(<name>.mjs|x)"`, is a fail-closed over-deny: the stripped text puts the name at a run position. A subagent searches with an unquoted name or splits the pattern. Two more fail-closed over-denies, accepted by the operator with no matcher change: a launcher word on one line pairs with the script name on a later line (`node x.mjs` newline `grep -n <name>.mjs cli/`), because the launcher branch joins tokens with `\s+`, which includes a newline; and a read-only command split with a backslash line continuation (`sed -n 1,20p \` newline `<path>`, `grep -n foo \` newline `<path>`), because the matcher removes the backslash and the newline then puts the path at a command head. A subagent keeps the read-only command and its path on one line. The ceiling of ADR 0297 stays: a script name assembled at run time by variable or command substitution is not caught. A shell glob or brace expansion of the file name (`merge-pr.m*`, `merge-pr.{mjs,}`) is not caught either, because the matcher requires the literal basename. Widening it to the bare stem would also deny `merge-pr.test.mjs` runs. Only the listed run forms are denied, and any other shell form that runs the script is uncaught, for example a brace group (`{ <path>; }`). The new ceiling also leaves these shapes uncaught: the path after a command prefix or keyword (`exec <path>`, `env <path>`, `timeout 60 <path>`, `nohup <path>`, `if <path>; then`, `sh -c '<path>'`), the path fed to an interpreter by stdin or `$(cat <path>)`, and other JS runtimes (`deno run <path>`, `tsx <path>`). `env node <path>` is caught, because the launcher word `node` matches after any whitespace. A launcher word earlier in an argv list (`grep -n node <path>`) stays denied, unchanged from the unresolve rule. The orchestrator-only rule guards against accidents and is not a sandbox. The orchestrator is the only actor allowed to run the script.
