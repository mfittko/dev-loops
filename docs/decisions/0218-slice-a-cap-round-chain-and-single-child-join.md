# 0218. Cap-round chain end, named refusal conditions, no-commit sequence close and single-child join

## Status

Accepted — 2026-10-30 ([issue 2462](https://github.com/mfittko/dev-loops/issues/2462), operator scope decision for Slice A).

Builds on ADR 0197, ADR 0208 and ADR 0213. Accepted records remain unchanged.

Numbering and scope deviation from the issue's Slice A rows: the rows name ADR 0216, but open PR 2997 uses 0217 and the record was renumbered to 0218 to keep the sequence collision-free. The rows also say `--artifact` returns `all_done` when the file parses as JSON. Decision 4 supersedes that wording: the join requires the terminal field or 10 unchanged seconds, and the final-on-write replacement is the follow-up slice on #2462.

## Context

PR 2992 reached four blockers. A base merge after the cap-round fixer commit read as round cap+1. The cap-round refusal named one catch-all remedy for four different conditions. A `commit_only` fixer without a commit left a stale sequence marker that the push refusal told the operator to delete by hand. A coordinator ended its turn while a single child ran.

## Decision

1. Chain-end base-only rule. `resolveCapRoundFixed` accepts a head M when the chain's last sealed clearing record names candidate B and M is a base-only merge since B (`isBaseOnlyMergeSince` against `origin/<baseRefName>`). `emit-fixer-work-order.mjs` applies the ADR 0197 base-only rule against the chain's last candidate B as well as the cap-round head, so M is the cap round. A merge that changes the PR-own patch, or a missing `baseRefName`, fails closed. The ADR 0197 rule and the sealed delta record format are otherwise unchanged.
2. Named refusal conditions. The cap-round refusal of `pr-gate-coordination.mjs` names the one failed condition and its remedy: `no_clearing_record`, `unsealed_record`, `items_do_not_cover`, `chain_does_not_reach_head` or `cap_round_unresolved`. `cap_round_unresolved` means the cap round could not be resolved (an unreadable findings ledger or config, no cap round with a verdict, or a resolver throw); `resolveCapRoundFixed` reports it on its null return and the detector reports it from its rejection handler. The refusal falls back to `cap_round_unresolved` when no condition is reported. `resolveCapRoundFixed` reports the condition through its `onFailure` callback.
3. No-commit sequence close. The remedy for the `PRE-PUSH-DELTA-PUSH-AUTHORITY` refusal is the existing authenticated no-commit closure of `check-pre-push-delta.mjs` (input-only, `--fixer-plan`, `--site-coverage`, outcome `no_commit`). The refusal names that command with the marker's baseline head, in both the act-list and the threads-file route form (the marker records no route), and no longer names marker deletion. A marker that names no branch (unreadable or malformed) cannot be authenticated by that close, so its refusal names no close command and no deletion; it says the marker names no branch and that the `PRE-PUSH-DELTA-PUSH-AUTHORITY` rule owns its recovery. A baseline that is not a full lowercase hex SHA (including an empty one) gets no close command, names the marker path, and the rule owns its recovery. No new subcommand is added.
4. Single-child join. On Claude Code a coordinator joins one child with `gate wait-for-units --artifact <path>`, a single-unit mode that returns `all_done` (the artifact parses as JSON and carries the terminal field its schema requires, for example `outcome` on a DeltaPrePushReviewResult, or, with no terminal field, stays unchanged for 10 seconds; the child writes no marker) and `timeout` with the remedy otherwise. Under this rule a parseable write with the terminal field satisfies the join at once, and a parseable write without it satisfies the join after 10 unchanged seconds, for every hand-back type, including a full-phase fixer outputRef that `--construct` writes before the verifier and `--check` finish. The coordinator reads the hand-back before it acts. The `--report-path` follow-up on #2462 replaces the window. The join keeps this terminal-field-or-10-second-stability rule in slice A. The final-on-write fix, a hand-back that is final on its first write, is the v1.0.9 follow-up slice on #2462 (`--report-path`), with a deadline of Tuesday 2026-11-03 evening. The hand-back path must not exist at dispatch: each fixer emission and each delta review invocation gets its own path, and the coordinator never reuses a hand-back path, because the join cannot tell a stale file from the current child's. The rule `COORDINATOR-SINGLE-CHILD-JOIN` forbids ending the turn before the join returns. Pi keeps the blocking dispatch (`async: false`), `runs.all` or `bg_wait`.

## Consequences

A base merge after a cleared cap-round fix reaches `mark_ready_for_review`. Each cap-round refusal carries one actionable remedy. A stale sequence marker closes through a sanctioned command. A single child gets a deterministic join on Claude Code.
