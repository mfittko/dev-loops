# 0042. Scope the single-contributor ownership gate to code-changing and merge-authoritative strategies only

## Status

Accepted — 2026-07-22 ([issue 1444](https://github.com/mfittko/dev-loops/issues/1444))

## Context

The single-contributor ownership gate ([0033](./0033-single-contributor-ownership-fail-closed.md)) is enforced in `scripts/loop/resolve-dev-loop-startup.mjs` on both the `--issue` and `--pr` startup paths, before the strategy for the run is selected. Because it ran ahead of strategy selection, it fired for every entrypoint through that seam, including a pure read-only `ui_review` (`/loop-review-ui`) start. A reviewer could not run a running-app review against a PR assigned to someone else, or against an unassigned PR — the exact artifacts a reviewer is most likely to be looking at. 0033 never actually decided that read-only review and wait/observe starts needed a claim; its Context and Decision describe "routing toward implementation or continuation" and Next Up pickup, and its Consequences describe the loop's run-singleton guarantee for contributors advancing claimed work — it does not name `ui_review` or `wait_watch` at all. The universal enforcement point was an implementation artifact of where the gate happened to be wired in, not a deliberate extension of 0033's decision to review/observe strategies.

## Decision

We scope ownership enforcement to the strategy selected for a given start, via a `STRATEGY_OWNERSHIP_GATE` map consulted after strategy selection: `ui_review` and `wait_watch` are exempt (pure read/observe — they never claim or write anything), and every code-changing or merge-authoritative strategy (`local_implementation`, `issue_intake`, `copilot_pr_followup`, `external_pr_followup`, `reviewer_fixer`, `final_approval`) stays gated exactly as 0033 requires, including the PR-path linked-issue foreign-ownership check. An unknown or future strategy not yet listed in the map resolves to gated (fail closed), so a newly added strategy is safe by default until someone deliberately exempts it. The existing `DEVLOOPS_OWNERSHIP_BYPASS` read-only escape hatch is unchanged and stays orthogonal: it remains available for tooling that previews routing without starting anything (e.g. `info.mjs`), while strategy scoping is now the primary mechanism for the common reviewer case. We rejected two alternatives: (1) leaving the gate universal and adding a separate `--force`-style override flag for reviews, which would require every review invocation to opt out explicitly and risks the override leaking into non-review starts; and (2) gating on the CLI flag (`--ui-review`) instead of the selected strategy, which would miss `wait_watch` (a state-derived strategy reachable with no dedicated flag) and would require a second, flag-shaped exemption mechanism alongside the strategy-shaped one. This is a refinement of 0033, not a reversal: 0033's decision text ("routing toward implementation or continuation requires assigned_to_me") is unchanged and still holds for every strategy it was ever applied to in practice; this record narrows where in the seam the gate is consulted and adds the two read/observe strategies 0033 never addressed. 0033's Status stays `Accepted`, per `ADR-SUPERSEDE-NOT-REWRITE` — a superseding record is for changes that reverse an existing decision's wording, and no clause of 0033 is reversed here.

## Consequences

A reviewer can run `/loop-review-ui` against any PR regardless of who — if anyone — it is assigned to, and a wait/observe start never needs a claim either. Every code-changing or merge start keeps 0033's fail-closed guarantee unchanged: `local_implementation`, `issue_intake`, `copilot_pr_followup`, `external_pr_followup`, `reviewer_fixer`, and `final_approval` all still require `assigned_to_me` (or `assigned_to_copilot` for the Copilot-first flow) and still fail closed with 0033's exact messages on foreign or unclaimed artifacts. Adding a new strategy to the routing evaluator without an explicit `STRATEGY_OWNERSHIP_GATE` entry defaults it to gated, so the fail-closed posture 0033 established survives strategy growth; deliberately exempting a future read-only strategy is a one-line, reviewable addition to the map rather than a re-audit of the whole gate.
