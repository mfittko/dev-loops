Trace

    Where the loops are

    • Refinement. The grill iterates until the issue has an AC / DoD matrix, Non-goals and a recorded results comment, or hands off honestly.
    • The gate round. Reviewers fan out over one head. Fan-in checks that every unit reported. The judge decides per finding; only the act list reaches the fixer. A fix makes a new head, and the round runs again.
    • Copilot follow-up. Request, wait, fix, reply, re-request, at most 5 rounds by default. A clean review on the same head ends it.
    • The outer loop. Every startup re-reads the record. The next unit cannot start while the previous merge lacks its retro checkpoint.

    What the record holds

    The state lives outside any one chat: the issue body and its matrix, the PR and its head SHA, CI, gate verdicts per head, the gate artifacts under tmp/, the board column and the retro checkpoint in .pi/.

    Each guard reads that record. A verdict counts only for the head it names. A changed spec makes every clearance from the old spec stale.

    A session can end and a new one can resume. Startup reads the same record and computes the same next step.

    Who decides what

    Agents write code, review it and judge findings. Scripts decide whether a step may advance: coverage, validation, head identity, size, tripwires and merge preconditions. The operator decides intent, waivers and the merge authorization.

    • Hooks deny raw gh pr merge, raw gh pr create and inline interpreters.
    • Scripts fail closed: an unknown result blocks, and a config error never relaxes a gate.
    • The operator can grant a standing authorization to merge on a clean full gate set.
