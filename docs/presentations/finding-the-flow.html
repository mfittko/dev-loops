Graph engineering

Old process ideas.
New kinds of workers.

State machines and workflows already describe steps, conditions, and recovery. Now some of those steps contain an AI agent.

“Graph engineering” is a growing umbrella. Here, we focus on controlling the workflow around the agent.

05 / 16

Fail closed

No evidence.
No permission to advance.

Check resultWorkflow response
PassAllow the next permitted step
FailRepair or reject
Unknown / check crashedBlock advancement; recover the evidence

A broken check must never silently count as a pass.

Security principle: OWASP: Fail Securely.

06 / 16

Loops need an exit

“Try again” needs a reason

What went wrong?What happens next?
Temporary tool outageWait, then retry within a budget
Bad outputRepair with feedback, then recheck
Send timed outFind out whether it sent before repeating
Attempts exhaustedStop and hand over to a person

A failed check changes the route. It doesn't lower the bar.

Evidence has an expiry condition

Approved which version?

10:00 · version A

Checked and approved

The message matches the order.

10:02 · version B

The agent changes the message

Approval for A doesn't cover B.

Bind evidence to the work it checked. Refresh changed facts before the next action.

Illustrative version rule; applied to real code revisions in the dev-loops example.

What this can promise

Predictable rules.
Fallible work.

With the same validated state and rules, code can choose the same permitted next step.

The agent can still write a wrong answer. A check can miss it. The workflow itself can be wrong.

Passing a gate establishes what that gate tested.
