### Fixed

- **`validatePrBodySpec` now requires checkbox markers for Acceptance criteria / Definition of done, closing a fail-open completeness-block hole (issue [#2333](https://github.com/mfittko/dev-loops/issues/2333)).** `extractPrBodyUncheckedChecklistItems` (the deterministic completeness block) only ever counts `- [ ]`/`- [x]` checkbox items; a plain `- ` bullet is invisible to it. `validatePrBodySpec` previously accepted plain bullets in AC/DoD sections via `extractChecklistItems` (which counts both bullet shapes), so a plain-bullet AC/DoD body could pass spec validation yet fail-open the completeness block. The validator now classifies AC/DoD items via the checkbox-aware parser and rejects any plain bullet under the new distinct codes `acceptance_criteria_not_checkboxes` / `definition_of_done_not_checkboxes` — scanning the SAME section set the completeness block reads (all matching headings, deep-flattened past `###` sub-headings), so a duplicate AC/DoD heading or a bullet nested under a sub-heading can no longer slip past either surface. `validateTrackerBackedPrBodySpec` inherits the requirement via delegation.
