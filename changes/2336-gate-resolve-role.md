### Added

- **A new `dev-loops gate resolve-role` CLI resolves a review operation's authoritative reviewer role, replacing a reviewer-side inline call into `resolveReviewerRole` (issue [#2336](https://github.com/mfittko/dev-loops/issues/2336)).** `@dev-loops/core/loop/review-operation` is the ONE operation-scoped authority for a review operation's legal candidate angle pool (`draft_gate`/`pre_approval_gate`/`spike` use the existing mandatory/static/additive gate pool; standalone `review` uses the static draft+pre-approval union, unchanged) and the reviewer role an authorized angle resolves to. `write-gate-context.mjs`'s standalone-review angle union now computes through this shared authority instead of recomputing it. `dev-loops gate resolve-role --gate <draft_gate|pre_approval_gate|review|spike> --angle <name> [--harness <pi|claude>]` loads the fully merged repo config and prints `{ persona, prompt, model, status, ... }`; exit 0 iff config errors are absent AND the angle is a legal pool member, nonzero otherwise — the one reviewer safety boundary. The `status` field (`resolved`/`fallback`/`prompt-missing`/`non-member`/`config-error`) is diagnostic only, never a second decision surface. Reviewer-facing prose (`agents/review.agent.md`, `skills/copilot-pr-followup/SKILL.md`, `skills/docs/gate-review-sub-loop-contract.md`, `skills/docs/gate-review-comment-contract.md`) now points reviewers at this CLI instead of an inline `resolveReviewerRole(config, angle)` call or a raw `extension-defaults.yaml` read (which misses a repo's `.devloops` override). No change to the fan-out emitter's own dispatch-time role resolution, gate evidence, fan-out/fan-in, provenance, or lifecycle semantics.
