- **PRs now record their changelog note as a changeset fragment instead of editing `CHANGELOG.md` directly (issue [#2293](https://github.com/mfittko/dev-loops/issues/2293)).** Each PR adds a NEW, uniquely named `changes/<slug>.md` fragment file; uniquely named fragments never collide, so concurrent PRs in a drain stop conflicting on the shared changelog and no longer force a base-move re-gate to resolve a CHANGELOG conflict. The changelog-completeness gate (`scripts/docs/validate-changelog-completeness.mjs`) now accepts a fragment in place of a direct `## Unreleased` edit (the legacy direct-edit path still passes for backward compatibility). At release, `scripts/release/bump-version.mjs` folds every pending fragment into the `## Unreleased` section via the new `scripts/release/assemble-changelog-fragments.mjs`, removes the consumed fragment files, and stamps `## Unreleased` to `## <version>` unchanged. Existing `CHANGELOG.md` content is preserved and historical entries are untouched. See `changes/README.md` and `skills/docs/pr-lifecycle-contract.md` (`LIFECYCLE-CHANGELOG-COMPLETENESS`).
