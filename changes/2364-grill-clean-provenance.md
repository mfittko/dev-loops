### Fixed

- **`grill_clean` now requires recorded grill provenance, not just a shape-clean detector result (issue [#2364](https://github.com/mfittko/dev-loops/issues/2364)).** A zero-open-gap `detect_gaps` pass previously short-circuited to `grill_clean` whenever `detectIssueRefinementArtifact` found a valid AC→DoD matrix, so any hand-authored matrix made the grill a silent no-op with no comment and no rationale. The zero-gap branch now resolves to `grill_clean` only when a `🔬 Grill / refinement results` comment is already posted on the target (with or without a recorded `bypass: operator-authorized by <handle>` line) or the surface is a `plan` file (shape-only, unchanged). `normalizeGrillSnapshot` gains `provenanceRecorded`/`provenanceBypass`, a new `detectGrillProvenance(comments)` helper computes them, the detector CLI gains `--comments-file <path>`, and every result now carries `reason`/`bypass`. Every semantic pass — including a zero-gap one — now posts the results comment stating its outcome, so a re-run of an already-recorded target still reaches the zero-iteration exit. See ADR [0084](docs/decisions/0084-grill-clean-requires-recorded-provenance.md), which amends ADR 0029.
