### Added

- **Pi gate fan-out now emits a ready one-call wave script, so a multi-unit round releases concurrently instead of silently serializing (issue [#2350](https://github.com/mfittko/dev-loops/issues/2350)).** `scripts/github/emit-wave-dispatch.mjs` turns the round's emitted `emit-plan.json` units plus their composed prompt bytes into one ready `subagent({ workflowScriptPath, cwd, async: false, timeoutMs })` call per wave, whose script body returns a single `runs.all([...])` with a unique non-empty `key` per dispatch unit and each unit's prompt bytes inlined verbatim. It honors `gates.fanout.maxConcurrent` per wave, keeps `gates.fanout.sequential: true` as the sanctioned single-unit load fallback, and the emitted wave fails closed on any other serialization instead of silently degrading a `gates.requireFanoutEvidence` gate (bypassing the emitter to compose per-unit calls is undetected at gate time). The legacy `tasks: [...]` top-level input is never emitted.
