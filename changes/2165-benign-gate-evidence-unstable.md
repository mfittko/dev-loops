### Fixed

- **`loop info` no longer reports a green gate as an unexplained `UNSTABLE` (issue [#2165](https://github.com/mfittko/dev-loops/issues/2165)).** The Gate-evidence detector keeps `cancel-in-progress`, so a chatty loop supersedes and cancels several `gate-evidence-runner` runs (and superseded queued `gate-evidence-reporter` runs cancel too); each leaves a `cancelled` check-run that drives GitHub's `mergeStateStatus` to `UNSTABLE` even when the required `gate-evidence` commit status on the head is `SUCCESS`. A new `classifyBenignGateEvidenceUnstable` helper (`@dev-loops/core/loop/copilot-ci-status`) labels that case benign — the `gate-evidence` status is green and the only non-success rollup entries are superseded Gate-evidence job cancellations — and `loop info`'s `Mergeable:` line now renders it as green-with-rationale instead of a bare `UNSTABLE`. Fail-closed: a failed (not cancelled) Gate-evidence job, a non-success `gate-evidence` status, or any other failing/pending check stays non-benign. The `cancel-in-progress` cancellation itself is unchanged. The required-context invariant (`MERGE-PRECOND-REQUIRED-CONTEXT-IS-STATUS`) — the `main` required status is the `gate-evidence` commit status, never either Gate-evidence job — is now documented on the merge-preconditions surface, so superseded job cancellations can never permanently block a merge.
