### Fixed

- **The Claude Code PreToolUse Bash gate now denies bare FILE-MARKER poll loops and no longer false-positive-denies a quoted issue body that merely mentions loop tokens (issue [#2317](https://github.com/mfittko/dev-loops/issues/2317)).** A new `commandIsFileMarkerPollLoop` classifier (`@dev-loops/core/loop/bash-command-classify`) catches a `while`/`until`/`for` loop that repeatedly tests for a file's existence/type/permission (`[ -f … ]`, `[[ -e … ]]`, `test -f …`, plus the broader bash FILE-test operator class `-[a-hkprsuwxGLNOS]`, e.g. `-r`/`-L`) and sleeps with no gated wait-tool — the orphan pattern for a `<tasks>/<id>.done` sentinel Claude Code never writes. Both this and the existing `commandIsSleepPollLoop` first strip quoted literal contents (`stripQuotedLiterals`) so a quoted `--body`/`--title`/echo payload that merely mentions the tokens as prose is not flagged. The quote-stripping now spans multi-line quoted values (dotAll) and preserves the real payload of any executable-code flag — a short-flag cluster CONTAINING `c` anywhere in the cluster (`-c`, `-lc`, `-ec`, `-cl`, `-ci`, `-cx`), an optional `--` terminator, `--command`, or `eval` — so a poll loop wrapped in `bash -lc '…'`/`bash -cl '…'`/`eval '…'` is still denied instead of blanked away. The quote-stripping also now preserves a quoted literal that itself contains a command substitution (`$(...)`) or backtick — that content executes regardless of the surrounding quotes, so a natural poll idiom like `while [ "$(gh pr view 5)" != MERGED ]; do sleep 5; done` is still denied instead of losing its `gh` token to blanking.
