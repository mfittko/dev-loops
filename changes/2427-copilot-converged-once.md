### Changed

- **One converged Copilot review now stands for later heads by default, with a strict opt-in (issue [#2427](https://github.com/mfittko/dev-loops/issues/2427)).** A code fix after a converged Copilot review no longer needs a new Copilot round, below or at the round cap; `pre_approval_gate` reviews the current head. The latest submitted Copilot review decides: it is converged with zero unresolved threads, no outstanding request, and a clean, headerless, or 🔵 body, or a 🟡/unrecognized body whose review opened its own thread or that a trusted copilot-body-disposition record names. `request-copilot-review.mjs` returns the new `suppressed_post_convergence` status below the cap, at the cap, and under `--force-rerequest-review`; the gate coordination detector and `copilot-pr-handoff.mjs` no longer reopen the cycle at the cap for a converged head; `merge-pr.mjs` grants the new `converged_once` disposition and names the source review in `copilotCarriedConvergence`. A never-reviewed PR, an unconverged latest review, and a current-head 🟡 without an operator record still fail `copilot_convergence`. Set `refinement.requireCopilotConvergenceAtLatestHead: true` to restore the previous rule (a new Copilot cycle for a significant post-convergence change, the docs-only carry, and `docs_only_suppression`). A copilot-body-disposition record now clears a current-head finding at merge only when it names the review that raised it. ADR 0090 records the change.
