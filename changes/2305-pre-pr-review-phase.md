### Added

- **Pre-PR review phase: a developer-briefed, fresh-context, general-purpose review pass before the first push (issue [#2305](https://github.com/mfittko/dev-loops/issues/2305)).** The dev-loop now runs one review left of the gate, at the cheapest fix point. After implementation is committed and before the branch is pushed or `dev-loops pr create` runs, the developer hands a mandatory review brief (what changed, what to scrutinize, risks/tradeoffs, corners cut) to ONE fresh-context general-purpose reviewer paired with an adversarial-enumeration checklist (errno classes, symlink file+dir, rename, empty input, malformed heading, path normalization). Findings are applied in-tree; the pass is ephemeral (no PR, comment, thread, or Copilot round), bounded to one general-purpose reviewer per round and at most two rounds, then the branch is pushed once. The full fresh-context fan-out `draft_gate`/`pre_approval_gate` still runs afterward as the authority — this is an additive pre-filter, not a replacement, and it produces no lifecycle-gate evidence. The reviewer's model is harness-agnostic and config-resolved via `resolveRoleModel` (a new `pre-PR-reviewer` role); no model is hardcoded. Operators opt into a strong per-harness model in `.devloops`; this repo opts the Claude-Code harness into Fable (model token `fable`; underlying identity `claude-fable-5-1`) while Pi inherits its default. Canonical contract: `skills/docs/pre-pr-review-contract.md`. Harness-agnostic (Pi + Claude Code).
